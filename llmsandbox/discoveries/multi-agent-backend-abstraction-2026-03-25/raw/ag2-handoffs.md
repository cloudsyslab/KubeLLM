# Handoffs
Try it on the AG2 Playground
See LLM and context condition handoffs live at [playground.ag2.ai](https://playground.ag2.ai) — no setup required.
Handoffs are the essential mechanism that controls how agents interact and pass control to each other in a group chat. If tools represent what agents can do and context variables represent what they know, handoffs determine where they go next.
## Introduction to Handoffs[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#introduction-to-handoffs "Permanent link")
Handoffs define the paths a conversation can take through your multi-agent system. They allow you to create sophisticated workflows where the right agent handles each part of a conversation at the right time.
### Why Handoffs Matter[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#why-handoffs-matter "Permanent link")
In any multi-agent system, you need to carefully control which agent speaks when.
Handoffs provide this control by:
  * Directing the conversation to the most appropriate agent for each situation
  * Creating predictable workflows with clear transitions
  * Enabling complex decision trees based on conversation state
  * Allowing dynamic adaptation to user inputs


### The Hospital Triage Analogy[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#the-hospital-triage-analogy "Permanent link")
Extending our hospital emergency room analogy, when a patient enters the ER, they first see a triage nurse who assesses their condition. The triage nurse then makes a critical decision:
  * For cardiac symptoms, transfer immediately to the cardiologist
  * For respiratory issues, send to the pulmonologist
  * For minor injuries, direct to the general practitioner
  * For severe trauma, rush to the trauma surgeon


Each medical professional follows specific "handoff protocols" that determine:
  * When they need to transfer a patient
  * Who they should transfer to
  * What information must be included in the handoff


These protocols ensure the patient receives the right care at the right time. In AG2, handoffs serve the same purpose for your conversational agents.
## Core Handoff Concepts[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#core-handoff-concepts "Permanent link")
Each agent in AG2 has a `handoffs` attribute that manages transitions from that agent. The **handoffs attribute is an instance of the[`Handoffs`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/handoffs/Handoffs/) class**, which provides methods for defining when and where control should pass:

```
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-0-1)# Access an agent's handoffs
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-0-2)my_agent.handoffs

```

### Transition Targets[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#transition-targets "Permanent link")
When defining a handoff, you specify a transition target - the destination where control should go. AG2 provides several types of transition targets:
  * [`AgentNameTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/transition_target/AgentNameTarget/): Transfer control to an agent by name
  * [`AgentTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/transition_target/AgentTarget/): Transfer control to a specific agent instance
  * [`FunctionTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/function_target/FunctionTarget/): Transfer control to a custom function that can run logic before determining the next transition
  * [`AskUserTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/transition_target/AskUserTarget/): Ask the user to select the next speaker
  * [`NestedChatTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/transition_target/NestedChatTarget/): Target that represents a nested chat configuration
  * [`GroupManagerTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/group_manager_target/GroupManagerTarget/): Transfer control to the group manager who will select the next speaker
  * [`GroupChatTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/GroupChatTarget/): Transfer control to another group chat (essentially a nested group chat)
  * [`RandomAgentTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/transition_target/RandomAgentTarget/): Randomly select from a list of agents
  * [`RevertToUserTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/transition_target/RevertToUserTarget/): Return control to the user agent
  * [`StayTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/transition_target/StayTarget/): Keep control with the current agent
  * [`TerminateTarget`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/transition_target/TerminateTarget/): End the conversation


Here's how you might use transition targets:

```
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-1-1)from autogen.agentchat.group import AgentTarget, RevertToUserTarget, TerminateTarget
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-1-2)
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-1-3)# Transition to a specific agent
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-1-4)target = AgentTarget(tech_agent)
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-1-5)

### Function Targets[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#function-targets "Permanent link")
A `FunctionTarget` allows you to hand off from an agent to a custom Python function, pausing the workflow so you can run arbitrary logic before deciding what happens next.
The function receives:
  * The most recent agent output (as a string)
  * The shared `ContextVariables`
  * Optionally extra arguments


It can perform any custom logic, and then returns a [`FunctionTargetResult`](https://docs.ag2.ai/latest/docs/api-reference/autogen/agentchat/group/targets/function_target/FunctionTargetResult/) that specifies the next transition target and includes a message for the next agent.
Some common use cases for `FunctionTarget` include:
#### Complex validation and handoff behavior[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#complex-validation-and-handoff-behavior "Permanent link")
It is often important to validate an agent’s output, particularly when its task is complex or has a reasonable chance of failure. While you can create validation agents, they often struggle to determine handoffs correctly and can clutter the group chat message history. Function Targets offer a cleaner solution: you can write custom validation logic and dynamically decide how to proceed.
#### Custom Data Flow Handling[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#custom-data-flow-handling "Permanent link")
AG2 handles agent context automatically, but it is often important for agents to have access to specific information stored in context variables or elsewhere. Function Targets allow you to fetch that information and include it explicitly as a message sent to the next agent.
#### Example[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#example "Permanent link")
Refer to this [example](https://github.com/ag2ai/ag2/blob/main/notebook/agentchat_function_target_example.ipynb), demonstrating a `FunctionTarget` being used to inspect and validate agent output.
### ReplyResults and Transitions[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#replyresults-and-transitions "Permanent link")

## Types of Handoffs[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#types-of-handoffs "Permanent link")
AG2 offers four main ways to define handoffs:
  * **LLM-based conditions** : Transitions based on the language model's analysis of messages
  * **Context-based conditions** : Transitions based on values in context variables
  * **After-work behavior** : Default transition when no LLM or context conditions are met and no tools are called
  * **Explicit handoffs from tools** : Direct transitions specified by tool return values


Let's explore each type in our triage example.
### LLM-Based Conditions[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#llm-based-conditions "Permanent link")
LLM-based conditions use the language model to determine when a transition should occur. This is useful when the decision depends on understanding the meaning of messages:

```

### Setting Default After-Work Behavior[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#setting-default-after-work-behavior "Permanent link")
After-work behavior defines what happens when an agent completes its work and no specific LLM or context-based handoff conditions are triggered. AG2 provides two levels of control for setting after-work behavior: **agent-level** and **pattern-level**.
#### Agent-Level After-Work Behavior[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#agent-level-after-work-behavior "Permanent link")
You can set the after-work behavior for an agent using the `set_after_work` method. This method takes a `Target` object as an argument, which defines what happens when the agent completes its work.

```
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-11-1)# Configure handoffs for advanced troubleshooting agent
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-11-2)advanced_troubleshooting_agent.handoffs.set_after_work(RevertToUserTarget())
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-11-3)
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-11-4)# General agent reverts to user after helping
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-11-5)general_agent.handoffs.set_after_work(RevertToUserTarget())

```

This approach is ideal when different agents in your system need different behaviors after completing their tasks.
#### Pattern-Level After-Work Behavior[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#pattern-level-after-work-behavior "Permanent link")
Pattern-level after-work behavior sets a default behavior for all agents in the group chat using the `group_after_work` parameter:

```
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-12-1)# Set pattern-level after-work behavior that applies to all agents
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-12-2)pattern = DefaultPattern(
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-12-3)    initial_agent=triage_agent,
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-12-4)    agents=[triage_agent, tech_agent, general_agent],
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-12-5)    user_agent=user,
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-12-6)    group_manager_args={"llm_config": llm_config},
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-12-7)    group_after_work=RevertToUserTarget()  # All agents revert to user when done
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-12-8))

```

This approach is useful when you want consistent behavior across all agents in your system, reducing the need to configure each agent individually.
#### Precedence and Override Behavior[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#precedence-and-override-behavior "Permanent link")
When both agent-level and pattern-level after-work behaviors are set, agent-level settings take precedence:

```
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-1)# Pattern-level setting applies to all agents
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-2)pattern = AutoPattern(
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-3)    initial_agent=triage_agent,
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-4)    agents=[triage_agent, tech_agent, general_agent],
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-5)    user_agent=user,
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-6)    group_after_work=RevertToUserTarget()  # Default for all agents
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-7))
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-8)
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-9)# Agent-level setting overrides pattern-level for this specific agent
[](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#__codelineno-13-10)tech_agent.handoffs.set_after_work(TerminateTarget())  # This overrides the pattern setting

```

In this example, `triage_agent` and `general_agent` will revert to the user after completing their work, while `tech_agent` will terminate the conversation.
The `group_after_work` parameter accepts any of the [transition targets](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#transition-targets) available in AG2.
#### Choosing the Right Approach[#](https://docs.ag2.ai/latest/docs/user-guide/advanced-concepts/orchestration/group-chat/handoffs/#choosing-the-right-approach "Permanent link")
Use `agent-level` after-work behavior when:
  * Different agents need different behaviors after completing their tasks
  * You want fine-grained control over conversation flow
  * Some agents should terminate while others should continue the conversation


Use `pattern-level` after-work behavior when:
  * You want consistent behavior across all agents
  * You're setting up a simple workflow where all agents should behave similarly
  * You want to minimize configuration overhead
