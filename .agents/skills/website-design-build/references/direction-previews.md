# Direction previews

Use during an explicitly authorized direction-room or refinement pass for new websites and broad redesigns. Build the first useful browser artifact before a long design system or full integration. Return the room at its review gate; direction selection and product integration belong to later explicitly started passes.

## Keep the board visual and traceable

The board should bring the decision's evidence and choices together:

- A broad but focused visual shelf of real screenshots/crops, motion samples, or interactive capture previews. Group by component or behavior; attach source link, local pack, what matters, capture state, and any fidelity gap.
- For motion-bearing sources, include a playable unedited live recording and an obvious route to the original WACZ/replay when the sidebar supports that evidence or the user has chosen a separate capture runtime for this task. Otherwise, show available sidebar evidence and label recording/archive/replay coverage incomplete. Keep package integrity, ReplayWeb receipt, replay behavior, and visual comparison as separate statuses; a still or isolated media sample is not enough.
- For a broad direction-room pass, default to three genuinely distinct, comparable full-page directions built against the same core brief and copy; follow an explicitly agreed different scope. Let the differences appear in structure, type, content density, imagery, section rhythm, and interaction; do not rely on color variants.
- One useful motion or interaction proof in each direction when it matters to the design choice. Label authored source, captured original, and inspired prototype distinctly.
- Full-size page links, a component strip when useful, and enough mobile layout to see the design survives narrow screens.

Make a page easy to inspect at a realistic viewport; don't expect someone to judge a whole design from tiny inert iframes. Side-by-side thumbnails are navigation into the previews, not the evidence itself. Use mobile screenshots or a clear viewport toggle. Put gaps beside the reference or direction they affect.

## Show page rhythm and real behavior

Show the hero and one or more representative sections in working detail, then sketch the remaining major sections enough to expose ordering, pacing, transitions, density, and the close. Use real supplied copy, assets, and product behavior. Schematic interface and draft content must be labeled. Never make up metrics, customers, testimonials, or product capabilities as visual filler.

If an original reference contains video, canvas/WebGL, an interactive hotspot, a product sequence, or scroll-linked scene, preserve the original WACZ/live page as a separate source example and make the board's corresponding behavior tangible. Do not imply the local direction is the original site. If an archive cannot replay the key state, use live observation and mark the missing capture signal.

Three directions should make different design decisions relevant to the audience and goal. An editorial, cinematic, and product-demonstration approach may be helpful, but use them only when those stories fit the brief.

## Iterate quickly

Keep the same task, content, and key proof in all directions so the user can react to design rather than changing claims. During an explicitly started refinement pass, combine the accepted components into one reconciled system and refresh affected screens. Retain alternate pages until selection is clear. Port approved intent and useful assets into the real site's stack only during an implementation pass; don't copy the disposable room wholesale when its architecture would complicate the product.

Show the first coherent room as soon as the differences can be judged. End the design-room pass with direct preview links and the decision needed next: choose a full direction or name the parts to combine in an explicitly invoked `$website-design` review. Selection records the decision; another `$website-design-build` invocation starts refinement or implementation. Do not wait for a perfect catalog before letting the user see the work.
